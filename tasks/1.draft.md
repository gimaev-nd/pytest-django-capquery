# Cоздать библиотеку для ускорения тестов django.

Это плагин для pytest. Он следит за запросами к БД, запоминает их и их результаты (далее capquery) в текстовых файлах. 
При повторном запуске тестов, проверяется есть этот запрос среди сохранённых capquery и если есть, то результат возвращается из него.
Поддерживается только postgres.

## Зависимости
Библиотека не работает с БД напрямую, а использует механизмы pytest-django

## Хранение
Собранные записи и их результы сохраняются в папке captures рядом с тестом. 

Нужно позаботится о том, чтобы не было конфликтов имён. Можно посмотреть как это сделано в https://github.com/vberlier/pytest-insta

При повторном запуске нужно собрать все данные из тестов и сложить их в inmemory sqlite. 

## Оптимизация
Нет смысла хранить в sqlite изначальный запрос, достаточно хранить его хеш. Алгоритм хеширования для запроса можно взять из https://github.com/Suor/django-cacheops

Библиотека должна работать, если тестов много. По умолчанию больше пяти. Эта величина должна задаваться или через параметр или через переменную окружения

Чтобы capquey постояно не менялись и не портили merge requests, нужно сбрасывать счётчики БД. Для этого к тестовой базе нужно применить команду django `sqlsequencereset`, делать это нужно до применения миграций. Для миграций тоже должны быть capquery. Нужно исследовать какие проблемы могут из-за этого возникнуть и решить их тоже.

## Поведение
1. Если для теста нет capquery, то в случае успешного выполнения теста capquery создаётся.
2. Если для теста есть все capquery, но какой-то запрос ушёл в БД, т.к. не нашёлся подходящий capquery, то тест нужно перезапустить и, в случае успеха, сформировать capquery снова.
3. Если для теста есть все capquery, и он упал, то тест нужно перезапустить и, в случае успеха, сформировать capquery снова. Нужен механизм отслеживания таких ситуаций, что не перегенерировать capquery бесконечно.
